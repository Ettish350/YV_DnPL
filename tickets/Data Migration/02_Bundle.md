# Object: Bundle

## Salesforce Object Details

| Property | Value |
|----------|--------|
| Object Label | Bundle |
| API Name | Bundle__c |
| Status | Draft |

`Bundle__c` already exists in `yv-partial` (custom object, label "Bundle", one record type "Master"). It currently has three fields besides the system ones: `Name` (Text 80, label "Bundle Name"), `Bundle_Type__c` (Picklist) and `Active_Bundle__c` (Checkbox, required). The object name is therefore not an open question; its reuse is the proposal here. Legacy entity: `new_tour_type` (ObjectTypeCode 10133, "סוגי פעילות יומית"), 88 rows in the "שדות" sheet. The DD (Doc 1 04-entities.md, "חבילה (Bundle, Custom)") says the Bundle is the equivalent of the existing activity type in Tahal.

Child object `Bundle_Item__c` also exists in `yv-partial`; it is out of scope for this file.

## Field Mapping

Mandatory columns per `Claude_Salesforce_Migration_Guidelines.md` (1-6), plus four added per `00-CONVENTIONS.md`: **Old API Name**, **Unique**, **Section**, **Questions**. Unique is left blank where neither the DD nor an instruction states a requirement. Where "[EXISTING CUSTOM]" follows an API name, the field already exists in `yv-partial`; every other custom field is proposed (new). Standard `Name` already exists. Lookup targets that are not decided are written as plain "Lookup" and raised in Questions.
