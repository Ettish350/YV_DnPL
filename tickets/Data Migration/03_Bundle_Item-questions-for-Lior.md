Companion to [03_Bundle_Item.md](03_Bundle_Item.md). That file holds the field mapping (8 rows) and the per-field notes. This file pulls every open point into one list, one question per row, so you can answer row by row.

**How to answer.**
- Every row has Anna's **Proposal**. Write **OK** to accept it, or write a different answer.
- Anything that is not a yes or no: write it in words.
- When you have answered, Anna updates `03_Bundle_Item.md` to match. Only after that are the fields built (Stage B, after approval). Nothing is deployed.

"Proposal" is Anna's working view, not a DD fact. "Why we ask" quotes the DD where it says something. "Not in the DD" means a search of `dd/` found nothing.

Questions in total: 14 (A: 5, B: 1, C: 3, D: 5).

Background: `Bundle_Item__c` already exists in `yv-partial` (one record type, "Master"). The YV fields workbook has no entity and no fields for it. The only legacy material is four many-to-many tables between `new_tour_type` (the Bundle, D-018) and `new_yv_product`, each with only the two GUID columns: `required`, `optional`, `no_cost`, `required_no_cost`.

The former single classification field was split into two, per instruction: `Requirement_Type__c` (חובה;רשות) and `Payment_Type__c` (בתשלום;ללא תשלום). The channel field was removed: a product's channel availability stays on Product2 (`Display_Channels__c`).
